# Готовность открытой беты

Дата: 13 сентября 2026. Исходная версия: 0782131. Подготовлен кандидат для локальной приёмки; публичное размещение не выполнено. Внешние условия выпуска перечислены ниже.

## Исправлено

- Доступ администратора определяется стабильной учётной записью, а не именем. JWT без настроенного секрета не создаётся. Проверяются подпись, срок, аудитория Google и принадлежность токена приложению.
- Telegram использует короткоживущие одноразовые ссылки. Одновременно потребить ссылку может только один запрос. Привязка идентичности не удаляет другой профиль и не объединяет аккаунты автоматически.
- Прогресс хранится раздельно по аккаунтам. Облачные записи выполняются последовательно с проверкой ревизии и транзакцией. Удаления сохраняются; конфликт с другим устройством требует явного выбора версии.
- Пропуски и неправильные ответы не дают зачёт упражнений. Повтор исправляет результат без двойного начисления. Прослушивание диалога не равно выполнению. Свободный чат не получает заготовленную похвалу при отказе ИИ.
- Запись голоса сама по себе не считается ответом. Текстовые транскрипции не получают выдуманную оценку произношения. Неполный разбор звонка отклоняется, низкая оценка грамматики не повышается искусственно.
- Записи доступны через защищённый API владельцу и администратору. Загрузка ограничена по размеру и частоте. Параллельные записи реплик сохраняются без потери соседних реплик.
- Запросы ИИ ограничены общим и индивидуальным бюджетом в PostgreSQL. Запросы к провайдерам имеют таймаут. Пользовательский ключ одного провайдера не передаётся другому.
- Подсказки организованы в три понятных шага с дополнительными деталями; автопоказ выключен по умолчанию и управляется одной настройкой. Исправлены клавиатурная навигация и ширина на телефоне.
- В бете отсутствуют предложения покупки и активные промокоды. Гостям открыты два урока; после бесплатного входа доступны все сто. Кнопка связи не перекрывает ввод ответа в уроке.
- Исправлены шесть неразрешимых заданий на сборку фразы и четыре ошибочных описания корней/слов в уроках 51 и 75.
- Next.js обновлён до 16.3.5, sharp до 0.35.4, js-yaml до 4.3.2. Исправлен неполный package-lock.json.

На отдельном локальном сервере проверены: вход тестового ученика А, перенос его гостевого этапа теории, сохранение после перезагрузки, выход и вход ученика Б без чужого прогресса. Запрос к БД подтвердил: у А сохранена теория первого урока, у Б завершённых этапов нет. Бесплатный аккаунт открывает третий урок.

При отключённом ИИ свободный чат показывает ошибку и повтор, сохраняет текст в поле и не даёт зачёт. На экране шириной 390 пикселей проверены подсказки и исправленная отправка сообщения без перекрытия кнопкой связи. Ранее браузером пройдены все пропуски, неправильный ответ с повтором и 12 правильных ответов; результат сохранялся после перезагрузки и не переносился на другой урок.

Сборка для локальной проверки использует ULPANA_THREADED_BUILD=1 и отдельный ULPANA_BUILD_DIR=.next-beta. Обычная команда npm run build использует Webpack и стандартный .next. Подготовлен GitHub Actions workflow; он ещё не запускался на GitHub. Полный lint показывается в нём отдельным предупреждением, остальные проверки обязательны.

## Условия перед публичным выпуском

1. Отозвать GitHub PAT, ранее записанный в адресе remote, и старый Groq-ключ из истории исходников. Их значения не включены в отчёт. Замена кода не отзывает старые секреты.
2. Настроить и проверить реальные Google/Telegram login, новый JWT_SECRET, APP_URL и секрет Telegram webhook. Провести вход и выход тестовым учеником на конечном HTTPS-домене.
3. Сделать резервную копию рабочей PostgreSQL и проверить восстановление. Новые таблицы и ревизии инициализируются транзакционно с блокировкой; миграцию рабочей базы здесь не выполняли.
4. Подключить закрытый R2/S3. Проверить отсутствие публичного доступа и миграцию либо удаление старых публичных записей. Настроить срок хранения: уникальные аудиофайлы пока требуют политики очистки; старые реплики более длинной попытки могут оставаться в истории записи урока.
5. Проверить реальные ответы выбранных ИИ-моделей и расход в кабинете провайдера. Лимит запросов в приложении не заменяет денежный лимит провайдера. Голос, микрофон и распознавание проверить отдельно в тихой обстановке на целевых устройствах.

## Ограничения оценки качества

Структурная проверка 1200 заданий не подтверждает педагогическое качество каждого урока. Полный лингвистический разбор всех ста уроков не проведён. Следующим этапом нужен поурочный аудит естественности иврита, огласовок, транскрипции, усложнения материала и качества обратной связи. Исправления языка должны иметь проверяемый источник; гипотезы модели не считать установленными ошибками.

Платный PRO не готовится к выпуску этой задачей. Перед изменением режима беты отдельно проверить оплату, срок доступа и серверные ограничения.

Порядок дальнейшей разработки и команды проверок описаны в DEVELOPMENT.md.
