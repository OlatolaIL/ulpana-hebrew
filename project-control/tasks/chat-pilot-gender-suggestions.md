## Проблема и ожидаемое поведение

Пункт 16 исходного аудита. В обычном ИИ-диалоге урока 5 шаг 3 содержит один общий образец «תּוֹדָה רַבָּה, כֵּן, אֲנִי צָרִיךְ שַׂקִּית.». Для ученицы образец первого лица должен иметь женскую форму, согласованную транскрипцию и перевод. Телефонная адаптация, принятая ранее, не влияет на этот отдельный путь.

Архитектор проследил код на e8148cc:

- src/components/LessonAiChat/useAiChat.ts: buildInitialMessage выбирает гендерное приветствие, но suggestedReplies берёт непосредственно из steps[0].sampleAnswers.
- src/app/api/ai/chat/route.ts: normalizeResponse получает isFemale, однако при недостатке suggestedReplies копирует nextStep.sampleAnswers без выбора формы.
- Там же исходящий промпт трижды использует исходные sampleAnswers: образцы для оценивания, примеры ответа и suggestedReplies следующего шага. Исправления только финального JSON недостаточно.
- Женский вопрос шага уже задан в aiQuestionHebrewFemale; менять его или род продавца по полу ученика не нужно.

## Реализация в пределах задачи

Предпочесть явную авторскую женскую версию образца и небольшой общий выборщик, используемый клиентом и сервером. Конкретную схему данных предложить в diff; она должна сохранять совместимость с уже существующими шагами. Не строить глобальный словарь замен окончания и не превращать любую мужскую форму в женскую: речь может идти о продавце или третьем лице.

Выбранная версия должна согласованно попадать в начальные подсказки, сценарные образцы исходящего промпта и резервные подсказки серверного ответа. Для шагов без явной версии сохранить нынешние данные и поведение. Основной воспроизводимый случай — урок 5, шаг 3; не менять темы, порядок/количество ходов, ключи сценария, авторизацию, лимиты, оплату или телефонное API. Сохранить защиту от применения запоздалого ответа после смены пола/сессии в useAiChat.

Нормативную форму и ударение сверить с реально прочитанным источником; согласовать с language-standard.md. Не выдавать исправление ручных образцов за доказательство того, что живая модель никогда не ошибается в роде.

## Критерии приёмки

1. Настоящий выбранный образец для ученицы содержит צְרִיכָה и соответствующую транскрипцию, мужская версия сохраняет צָרִיךְ. Общие формы и род собеседника не изменены. Сравнение остальных полных данных покажет точную область правки.
2. Реальный buildInitialMessage и реальный POST /api/ai/chat проверены с обоими полами. Перехватить исходящий запрос к провайдеру и проверить все упоминания сценарных образцов; не ограничиваться отдельным helper.
3. Синтетические ответы провайдера с 0 и 1 валидной подсказкой вызывают правильный резервный набор следующего шага. Обычный ответ с 2 валидными подсказками сохраняет установленный контракт. Ошибки/недоступность провайдера не превращаются в выдуманный успешный диалог.
4. Добавить компактный тест регрессии, обнаруживающий прежний путь реального компонента/маршрута. Старый код подставлять только в тестовый процесс; не сохранять тавтологический тест копии старой формулы.
5. Проверить фактическую смену пола/сессии и прежние проверки запоздалого ответа. Применимые обязательные проверки DEVELOPMENT.md; прежний долг lint сравнить с базой, не маскировать новыми исключениями.
