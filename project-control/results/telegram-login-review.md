# Приёмка диагностики Telegram-входа

Архитектор ChatGPT, 14 сентября 2026 (проверка сервера 13 сентября 20:59:54 UTC).

**Исправление не принято: боевой вход остаётся заблокирован.** Gemini подготовил отчёт и сообщил о настройке секрета вебхука со стороны Telegram и в локальном окружении. В Vercel изменение не применено; сквозной вход не проверен.

Независимые запросы подтвердили: `POST /api/auth/telegram` с пустым JSON — 401, создание polling-сессии — 503, GET без токена — 400, вебхук без секретного заголовка — 503. Значения токенов не выводились. Результаты: `project-control/evidence/telegram-public-checks.json`.

## Что установлено и что ещё требует проверки

- По текущему коду основная JWT-проверка проходит. Проверка старого Telegram-маршрута показывает непустое значение bot token, но не доказывает его валидность: отсутствие подписи отклоняется раньше проверки токена у Telegram. Более того, эта проверка не делает `trim`, в отличие от polling-маршрута.
- Поэтому `TELEGRAM_WEBHOOK_SECRET` — сильная основная гипотеза отсутствующей настройки по коду и ответам сервера. Утверждение «настройки Vercel прочитаны, переменная точно отсутствует» не подтверждено: кабинет не открыт. Не исключены различия переменных активного деплоя и локального окружения.
- Успешный `getMe` с локальным токеном проверяет локальный токен; его равенство значению Production пока не доказано.
- Коммит `ec4d663` подтверждает локальное состояние. Версия активного Vercel Deployment не установлена через кабинет/API. Нельзя выдавать её за установленную по одному локальному Git.
- Сведения Gemini о setWebhook, локальной записи секрета и схеме БД пока являются результатом исполнителя. `getWebhookInfo` не возвращает secret_token, поэтому сам по себе не подтверждает ни прежнее отсутствие, ни совпадение секрета.
- `.env.local` игнорируется Git (независимо проверено). Секреты не должны попадать в отчёты, Git, URL инструкций или скриншоты.

## Конкретный блокер доступа

Gemini сообщил `vercel whoami: Logged out`. Архитектор открыл `https://vercel.com/dashboard` в доступном браузере Codex: перенаправлено на страницу Login. Chrome недоступен инструменту браузера. Отсутствие браузерной авторизации подтверждено. Следующий необходимый шаг для размещения — пользователь входит в Vercel в доступном браузере либо подключает штатный доступ. Новый токен доступа не запрашивался и не создавался.

## Поправки к плану исправления

1. Проверить активный деплой и имена переменных в **Production**, не раскрывая значения. Не распространять секрет боевого бота на Preview и Development без необходимости; для них нужны отдельные конфигурации.
2. Если отсутствует webhook secret, синхронизировать Production с уже установленным у Telegram значением. Не генерировать ещё один секрет при каждом повторном запуске.
3. Применить конфигурацию новым размещением и повторить проверки. HTTP 200 после этого — ожидаемый результат, а не гарантированный: может проявиться следующая ошибка.
4. Выполнить полный вход с разрешённым тестовым аккаунтом. До этого отмечать только подтверждённые серверные части.
5. **Не выполнять предложенный Gemini откат с удалением секрета/вебхуком без секрета.** Он возвращает неисправный либо несогласованный режим. При неудаче сохранить отказ по умолчанию и исправить согласованность конфигурации; восстановление возможно только к известной безопасной паре настроек. Очередь Telegram не очищать, чужие сессии не сбрасывать.
6. В таблице Gemini переход JWT «503 → 400» относится к более раннему инциденту и не является результатом данной задачи: перед её началом JWT уже проходил проверку.

Код приложения архитектор не изменял. Пока нужен вход в Vercel, продолжается независимая работа над пилотом. Статус задачи — заблокирована доступом; это не останавливает весь проект.
