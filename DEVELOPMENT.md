## Совместная работа IDE

Одна задача — одна ветка и отдельный checkout/worktree. Одновременно редактировать один каталог из двух IDE нельзя: это смешивает изменения и делает результаты проверок недостоверными. Перед передачей задачи другой IDE фиксировать список принадлежащих ей файлов, ожидаемое поведение и способ проверки. После её завершения смотреть diff и самостоятельно запускать проверки.

Роли и общие правила определены в AGENTS.md. Gemini рассматривается как middle/senior-разработчик, которому ChatGPT как архитектор ставит задачи и проверяет результат. Изменения авторизации, синхронизации, оценивания и схемы данных требуют отдельного ревью. Исправления от модели нельзя принимать только по её отчёту.

Перед началом работы с кодом смотреть git status, AGENTS.md, раздел рабочего контекста в DEVELOPMENT.md и RELEASE_READINESS.md. Текущий этап, открытые вопросы и краткую передачу контекста хранить в разделе рабочего контекста этого файла; подтверждённые результаты проверки готовности — в RELEASE_READINESS.md. Очищать контекст по расписанию не требуется; короткий журнал должен позволять продолжить работу без истории переписки.

## Проверки

Использовать Node.js 24 и зависимости из package-lock.json.

```sh
npm ci
npm run typecheck
npm test
npm run build
npm audit --audit-level=high

```


Полный lint пока содержит технический долг; workflow показывает его отдельным предупреждением. Проверка типов, тесты, сборка, аудит зависимостей и lint трёх критических компонентов обязательны. Перед выпуском пройти интерфейс гостем и двумя тестовыми учениками: пропуск/ошибка/повтор упражнения, сохранение после перезагрузки, вход/выход, изоляция аккаунтов, недоступный ИИ, мобильные подсказки, клавиатура. Голосовые сценарии проверять отдельно в тихой обстановке с тестовым голосом.

## Регламент выгрузки на боевой сервер (Deployment Flow)

Выгрузка изменений на боевой сервер (production) строго регламентирована:
1. **Полномочия:** В соответствии с `AGENTS.md`, выгрузка выполняется **исключительно по прямому поручению пользователя**. Самовольная публикация запрещена.
2. **Обязательные предварительные проверки:** Перед коммитом и выгрузкой должны успешно проходить:
   ```sh
   npm test
   npm run build
   npm run typecheck
   ```
3. **Контроль состояния рабочей копии:** Выполнить `git status`, убедиться в отсутствии непредусмотренных или временных файлов и корректности затронутых изменений.
4. **Коммит и отправка:**
   - Зафиксировать изменения информативным коммитом (Conventional Commits: `fix(...)`, `feat(...)` и т.д.).
   - Выполнить `git push origin main`. Удалённый репозиторий GitHub (`OlatolaIL/ulpana-hebrew`) настроен на приём изменений по защищённому токену доступа (PAT).
5. **Автоматический деплой на Vercel:** Vercel подключён к репозиторию GitHub и автоматически собирает каждый пуш в ветку `main`. Результат обновляется на `https://ulpana-hebrew.vercel.app`.
