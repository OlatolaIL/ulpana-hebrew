# Разработка открытой беты

Сейчас выпускается бесплатная бета: гостям доступны первые два урока, после входа — все сто. Платежи и промокоды не включать без отдельной реализации и проверки биллинга.

## Совместная работа IDE

Одна задача — одна ветка и отдельный checkout/worktree. Одновременно редактировать один каталог из двух IDE нельзя: это смешивает изменения и делает результаты проверок недостоверными. Перед передачей задачи другой IDE фиксировать список принадлежащих ей файлов, ожидаемое поведение и способ проверки. После её завершения смотреть diff и самостоятельно запускать проверки.

Gemini подходит для ограниченного аудита контента, повторяющихся исправлений и небольших компонентов. Изменения авторизации, синхронизации, оценивания и схемы данных требуют отдельного ревью. Исправления от модели нельзя принимать только по её отчёту.

Перед началом смотреть git status и RELEASE_READINESS.md. Незавершённые решения и подтверждённые результаты хранить в этом файле. Очищать контекст по расписанию не требуется; короткий журнал должен позволять продолжить работу без истории переписки.

## Проверки

Использовать Node.js 24 и зависимости из package-lock.json.

```sh
npm ci
npm run typecheck
npm test
npm run build
npm audit --audit-level=high
npm run lint
```

Полный lint пока содержит технический долг; workflow показывает его отдельным предупреждением. Проверка типов, тесты, сборка, аудит зависимостей и lint трёх критических компонентов обязательны. Правила не отключались для сокрытия ошибок. Workflow подготовлен локально; успешный запуск GitHub Actions можно утверждать только после реального прогона.

Интеграционные тесты требуют отдельную PostgreSQL: 127.0.0.1:55433, база ulpana_beta_test. Перед npm run test:db установить TEST_DATABASE_URL для этой базы. Тесты отказываются запускаться на другом адресе и очищают собственные данные. Никогда не направлять их в рабочую БД.

Перед выпуском пройти интерфейс гостем и двумя тестовыми учениками: пропуск/ошибка/повтор упражнения, сохранение после перезагрузки, вход/выход, изоляция аккаунтов, недоступный ИИ, мобильные подсказки, клавиатура. Голосовые сценарии проверять отдельно в тихой обстановке с тестовым голосом.

## Секреты и данные

Секреты задаются в окружении размещения и не попадают в исходники, URL, журнал или отчёт. Авторизацию подписывать новым независимым JWT_SECRET. Telegram webhook должен проверять секретный заголовок. Записи голоса хранить только в закрытом R2/S3; их выдаёт защищённый API.

Сохранять резервную копию базы перед выпуском. Проверять восстановление отдельно. На время беты ограничивать общий бюджет ИИ и расходы в кабинете провайдера. Смена версии или перезапуск сервера не сбрасывает лимит в БД.
